# 実装方式


YouTube.js 18.3.0でYouTubeのプレイヤーを解析し、TV向けAPIから6ch音声を取得します。328（E-AC-3）を優先し、取得できなければ380などの6ch音声を試します。URLの必要な処理はネットワーク・拡張機能APIにアクセスできないsandbox内で行います。

MP4のsidx索引から約10秒単位の時刻とバイト範囲を読み取り、必要な範囲を取得します。FFmpegのWebAssembly版で各区間を6chのFLAC（24bit PCMから符号化）に変換し、Web Audioの6ch AudioBufferとして再生します。デコーダーの履歴を補うため、直前の1フラグメントも読み込み、不要な部分を正確に切り落とします。

現在区間と次の2区間を、ブラウザでは同じAudioContextの時計上へ予約します。Atmosでは6chの浮動小数点PCMを分割転送し、Windowsの出力クロック上で再生します。再生位置・速度・音量をページから通知し、シークやモード変更で古い予約・転送を中止します。区間ごとにaudio要素を読み直す方式ではありません。デコード済みキャッシュは最大3区間・96MiBで、過去や遠方の区間は破棄します。音声全体は保持しません。オフ時は先読みも中止します。長時間再生中に配信URLが期限切れになった場合は、索引の一致を確認してURLを更新します。

映像はYouTube内蔵プレイヤーのままです。MediaSourceへ328を直接差し込まず、標準音声をミュートして代替音声を同期させます。

音声取得はログイン情報を送らない匿名リクエストです。インターネットの通信先はYouTube / Googlevideoのみです。AtmosはNative MessagingでPC内の専用出力プログラムへPCMを渡します。音声出力プログラムはネットワークやシェル操作を行いません。通常のYouTube再生リクエストを書き換えず、`ys51=1`を付けた独自リクエストだけヘッダーを補います。
