# YouTube Original 5.1

ビルド日を版の識別に使用します。日付は日本時間（JST）基準です。配布ファイル名と拡張機能の表示で確認できます。

YouTubeページ内で、動画が持つ**元の5.1ch音声**を再生するChrome / Edge向け拡張機能です。標準音声とのオン／オフ、シーク、20分を超える動画の区間再生に対応します。2ch音声のアップミックスは行いません。

非公式の実験的なソフトウェアです。YouTube・Google・Dolby・DTSとは関係ありません。対応する6ch音声が取得できない動画では、標準音声を使用します。yt-dlpの導入は不要です。

## 導入

1. [GitHub Releases](https://github.com/ykrfg/youtube-51ch-chrome/releases) から、最新ビルド日の `youtube-original-5.1-日付-windows-x64.zip`（例：`youtube-original-5.1-2026-10-26-windows-x64.zip`）をダウンロードして展開します。導入用ZIPと開発用ソースZIPは別配布です。
2. 展開先は、後から移動しない場所に置きます。
3. Chromeで `chrome://extensions`、Edgeで `edge://extensions` を開きます。
4. 「デベロッパーモード」をオンにし、「パッケージ化されていない拡張機能を読み込む」で **extensionフォルダ**を選びます。
5. YouTubeの動画ページを再読み込みします。

HRTFモードは拡張機能だけで動作します。Windows空間音響モードは、次の追加設定が必要です。

### Windows空間音響を使う場合

1. `native/Install.cmd` を実行します。現在のWindowsユーザー向けに、ChromeとEdgeのNative Messagingホストを登録します。管理者権限は不要です。
2. Windowsの既定の出力機器で、Dolby Atmos for Headphones、DTS Headphone:X、Windows Sonic for Headphonesなど、使用する「空間サウンド」を有効にします。
3. YouTubeを再読み込みし、拡張機能の「Windows空間音響（Dolby／DTS）」を選びます。

補助プログラムはWindows x64用です。ソースからMSVCでビルドして同梱しており、コード署名は付けていません。登録時に生成する設定ファイルには、そのPC上の実行ファイルの絶対パスが入ります。この生成ファイルはリポジトリや配布ZIPには含めません。

解除は `native/Uninstall.cmd` で行います。補助プログラムの保存先を移動した場合は、移動先で `Install.cmd` を再実行してください。

## 出力モード

| モード | 出力 | 必要なもの |
|---|---|---|
| HRTFヘッドホン（初期値） | 元の6chを方向別に処理したステレオ | 通常のヘッドホン |
| Windows空間音響（Dolby／DTS） | Windows Spatial Audioへ6ch PCMを出力 | Windows x64、補助プログラム、対応するOS設定 |
| 6chスピーカー／通常ミックス | Web Audioの6ch出力。出力環境が2chなら通常のダウンミックス | ブラウザが認識する出力機器 |

Windows空間音響モードはOSで選択したプロバイダーを使用します。Dolby／DTSのライセンス状態を判定する機能や、Atmos／DTS:Xへのエンコード、ビットストリームのパススルー、高さチャンネルの生成はありません。DTS Headphone:X固有の出音やDTS:X Ultra等のメーカー独自機能は未検証です。

## 使い方

動画ページの「5.1ch」ボタンでオン／オフします。オン時は標準音声をミュートし、元の6ch音声を映像に同期して再生します。準備中や取得に失敗した場合は標準音声を維持します。

**「取得中」の表示で止まった場合は、5.1chを一度オフにしてからオンにし直してください。** 準備中は「準備をキャンセル」を押し、続けて「5.1chを有効にする」を押すとやり直せます。

- 内蔵プレイヤーの再生・停止・シーク・音量・速度変更に追従します。速度変更では音程も変わります。
- オフにすると標準音声へ戻ります。映像の再生位置は変えません。
- 「対応動画では自動で5.1chを有効にする」は初期値オフです。手動でオフにした動画では自動で再オンにしません。
- 5.1chオン中の消音には、拡張機能側のミュート操作を使います。標準プレイヤーのミュートは、標準音声を止めるために使用しています。
- モードと自動有効化設定をローカルに保存します。リロード時のミュート復元にはタブのsessionStorageを使います。
- 広告中や動画移動時は代替音声を停止します。
- 自動有効化では、ページ遷移の完了を待って次の動画を準備します。準備中に処理フレームが失われたり、進捗通知が35秒間途絶えた場合は1回だけ初期化をやり直します。再び停止した場合は標準音声へ戻し、無限に再試行しません。

元音声と標準音声ではラウドネス補正やDRCが異なる場合があります。オン／オフは音量を一致させたABXテストではありません。

## 対応範囲と既知の制限

- 公開された通常動画の、取得可能な6ch MP4音声とsidx索引が対象です。ライブ、DRM、ログイン必須の動画は対象外です。
- **動画時間に20分の上限はありません。** 必要な約10秒区間だけを取得・変換します。デコード済みキャッシュは最大3区間・96MiBです。作業領域を含むプロセス全体のメモリ上限ではありません。
- 非公開APIと配信側の挙動に依存します。動画や時期によって403やタイムアウトが発生する可能性があり、全動画の動作は保証しません。
- 発行直後の音声URLが一時的に403を返す事例に対し、最初の初期化領域だけ、3秒・4秒の間隔で最大2回再確認します。API要求・索引・通常区間にこの待機は適用しません。初期化全体の上限は90秒です。
- 出力機器の遅延によって同期誤差が残る場合があります。一般的なHRTFの定位感には個人差があり、頭の動きには追従しません。

検証内容と確認範囲は [検証記録](TEST_RESULTS.md) を参照してください。

## 更新

配布物は `2026-10-26` のようなビルド日で識別します。同じ日の再配布は `2026-10-26-1` のように番号を付けます。

新しいWindows用ZIPを展開し、読み込み元の `extension` フォルダを更新してから、拡張機能管理画面とYouTubeページを再読み込みします。開いたままのYouTubeタブも再読み込みが必要です。GitHub配布版の更新は手動です。

拡張機能だけを更新し、補助プログラムを同じ場所で使い続ける場合は再登録不要です。補助プログラムの更新・再登録が必要な場合は、そのReleaseの案内に従ってください。保存先を移動した場合は再登録してください。

## 通信・権限

実行時のインターネット通信先はYouTubeとGooglevideoです。音声取得はCookie等のログイン情報を送らない匿名リクエストで、独自の解析・広告配信・利用統計のサーバーはありません。

| 権限 | 用途 |
|---|---|
| YouTube / Googlevideoへのアクセス | 動画情報と音声区間の取得 |
| declarativeNetRequestWithHostAccess | 拡張機能自身のTV向けAPI要求に限りヘッダーを設定 |
| storage | モードと自動有効化設定の保存 |
| nativeMessaging | Windows空間音響の補助プログラムへのPCM転送 |

補助プログラムの音声出力処理はネットワーク通信を行いません。インストール操作では、現在のユーザーのChrome / Edge用Native Messaging登録とローカル設定ファイルを作成します。
